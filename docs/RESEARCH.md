# Prior-art research

Survey run on 2026-09-23 to decide what DomainScope should add. Three parallel surveys (GitHub projects, web tool UX, DevOps pain points) → 40 merged candidates → live feasibility verification → [ROADMAP.md](ROADMAP.md).

Notes on this file:

- The prototype scripts cited below (research/tls_lab.py, research/dnssec_check.mjs, research/dnsbl_check.mjs) and the screenshots (shots/…, research/shots/…) were local scratch artefacts of the survey and are **not committed**; their measurements are recorded in the tables here.
- Measurements against third-party organisations are anonymised ("a large telco", "a large e-commerce brand"): the product is global and the repo does not single out anyone's configuration. Public infrastructure (root / TLD / resolver name servers, CDN ranges) is named where the fact depends on it.
- Measurements of DomainScope's own discovery engine (recall, false positives, origin candidates, throughput) are in [Measured results (2026-09-23)](#measured-results-2026-09-23) at the end.

### UI patterns

- web-check: one card per check with collapsible description, use cases and links, plus JSON export per card
- propgate: four verdicts (pass, warn, fail, indeterminate) with the lookups that produced each verdict
- Zonemaster: results grouped by module, with a level filter (INFO to CRITICAL)
- 42wim/dt: one table row per authoritative nameserver (IP, ASN, RTT, serial, DNSSEC)
- MyIP: resolver answers grouped by country, '?' keyboard-shortcut sheet, shareable report link
- dnstwist.it: table fills in live as names resolve, with a column naming the generator
- cdncheck: compact provider tags next to each IP
- DNSViz: chain-of-trust diagram for DNSSEC
- Findomain/sublert: diff view of what changed since the last run

### Ideas raised

| Idea | Where | Effort | Inspired by | Description |
| --- | --- | --- | --- | --- |
| Import zone exports (Cloudflare BIND, Route53 JSON, octoDNS YAML) | both | M | DNSControl get-zones, octoDNS, Cloudflare zone export | The user pastes or drops their own zone export. That gives an exact hostname inventory with no guessing between sources. Cloudflare exports mark each record with cf_tags=cf-proxied:true/false, confirmed in cloudflare-docs import-and-export.mdx, and the record value is the real origin the owner configured. Proxied names can then map straight to inventory servers. |
| Remote certificate check via Globalping | browser | M | tlsx, MyIP | For public servers, run an HTTPS measurement against the IP with the hostname in the Host header. The result shows the served certificate's fingerprint and expiry, whether it matches the new certificate, and chain validity. The same check can confirm a rollout from several countries. Anonymous use allows 250 requests per hour, and users can add their own token. |
| Real-probe DNS and per-nameserver checks | browser | M | 42wim/dt, MyIP | Add a Globalping mode to Global DNS. It resolves from real probes by country or ASN, queries each authoritative nameserver directly (for SOA serial consistency), and can run a DNS trace. |
| Zonemaster deep test in Domain Health | browser | S | Zonemaster | Start a Zonemaster test, poll its progress, and group the results by module and level. The API has no Turkish, so the UI would map testcase ids to its own TR strings. |
| ACME Renewal Information (ARI) window | both | S | RFC 9773 | From the parsed certificate, compute the certID (base64url of the AKI, a dot, then base64url of the serial DER) and fetch the CA's suggested renewal window. Let's Encrypt sends ACAO * (verified). Sectigo returns data but without ACAO, so it belongs in the CLI. |
| Certificate expiry calendar and CAA builder from CT | browser | M | SSLMate certspotter | A timeline of currently valid certificates per domain, flags for issuers that are not expected, and CAA records generated from the CAs actually in use. Adding &amp;deduplicate=Y to the crt.sh query cut the rows from 131 to 74 in a test. |
| DNSSEC health: RRSIG expiry and DS/DNSKEY match | browser | L | DNSViz, 42wim/dt | Fetch DS and DNSKEY with the DO bit, check the DS digest with WebCrypto SHA-256, and show countdowns to RRSIG expiry. A later step could verify signatures (RSA, ECDSA P-256, Ed25519). |
| Filtering-resolver block check | browser | S | web-check Block Detection | Query the filtering resolvers and report blocks: an answer of 0.0.0.0 or an EDE 16/17 code. security.cloudflare-dns.com was verified with ACAO *. |
| IP intel enrichment | browser | S | Internet.nl, web-check | Add RPKI validity (RIPEstat network-info, then rpki-validation), the abuse contact, and Shodan InternetDB open ports for your own IPs. InternetDB sends ACAO *, but its terms need checking. |
| HTTP security grade per host | browser | S | web-check | Get a Mozilla Observatory grade with a simple POST (no preflight, ACAO *). |
| Naming-pattern expansion for your own zones | browser | M | alterx, dnsgen, puredns | Generate candidate names from the names already found using alterx/dnsgen-style patterns, resolve them through DoH with a query budget, and detect wildcards at every level. |
| SPF evaluator and misconfiguration hints | browser | M | DO SPF explainer, propgate | Answer 'does IP X pass SPF?', count void lookups, and detect a zone name the provider appended twice (such as _dmarc.example.com.example.com). |
| Provider range refresh | both | M | cdncheck fingerprint-update workflow | Run a scheduled GitHub Action that regenerates vendored ranges from sources without CORS (Cloudflare, Fastly, CloudFront, Google). Fetch the sources that allow CORS at runtime: AWS ip-ranges.json, Gcore, Oracle, api.github.com/meta, Bunny, and RIPEstat announced-prefixes. Classify Cloudflare in two tiers: proxied (official list) and Cloudflare network (ASN-derived). |
| CLI: more TLS ports and chain checks | cli | M | testssl.sh, tlsx, knockpy | Probe implicit-TLS and STARTTLS services (465, 993, 995, 636, 25/587 via smtplib), verify the served chain against the system trust store, and warn when TLS 1.0 or 1.1 is still enabled. |
| CLI: split-horizon resolution and outputs | cli | S | dnsx, ssl_exporter | Resolve names with the internal resolver and add those IPs as probe targets automatically. Add JSONL output, a Prometheus textfile output with ssl_exporter-style metric names, and an Ansible inventory of NEEDS_UPDATE hosts. |
| Export observed records as IaC | browser | M | DNSControl, octoDNS | Export the observed records as a BIND zone, dnsconfig.js, octoDNS YAML or Terraform. |

### UI patterns

- Search-first header: one universal input, always visible and focused with '/' or Ctrl+K. It auto-detects domain / IP / CIDR / ASN / URL / PEM / multi-line list and routes to the right view (MxToolbox SuperTool, ipinfo 'Type / to search'). It also accepts prefix commands such as 'mx:', 'global:', 'health:', 'bl:', 'cert:', 'ptr:'. Show a '?' overlay listing all shortcuts (MyIP).
- Command palette (Ctrl+K) listing views, recent queries from localStorage, and actions (theme, language, export CSV/JSON, copy permalink, re-run).
- Type chips instead of a select on Lookup: one row of toggle buttons (A AAAA CNAME MX NS TXT SOA CAA HTTPS SVCB SRV DS DNSKEY TLSA PTR) that re-query instantly and update the hash, e.g. #/lookup?name=x&amp;type=MX (Google Admin Toolbox Dig).
- Streaming job progress line plus per-job status: 'Running 7 of 9 checks (4.2s) · 1 issue', with 'Show load state' expanding a table of each source/check (pending / ok / rate-limited / error, ms). Every result card gets its own retry button and an (i) explainer, so one failed source never blocks the page (web-check).
- Advisory rollup at the top of every result page: collapsible 'Errors (n) / Warnings (n) / Info (n) / Passes (n)' aggregated across all cards, with passes collapsed by default (web-check Advisory, MxToolbox 'Show All Tests').
- Health summary: a percentage score bar, category tiles (DNS / Email / TLS-CAA / DNSSEC / Registration) each with error/warn/pass counts and a colored bottom stripe, and a problems-only table with 'How to fix' links (MxToolbox Email Health, internet.nl).
- Plain-language verdict sentences with a next action under every section heading ('DNSSEC is not enabled. Ask your DNS provider to add a DS record at the registrar'), then a 'Show details' disclosure with the raw checks (internet.nl). Tag each check 'High impact · Low effort' (Hardenize).
- Propagation view: a world map (vendored Natural Earth SVG, no CDN) with pins colored by answer group rather than simple ok/fail. Group 1 = the majority answer and gets the primary color; other groups get distinct colors with text labels. The legend shows 'Group A: 140.82.121.4 (18 locations)'. The list sits beside the map and hovering a row highlights its pin (whatsmydns, dnschecker).
- 'Expected value' field on propagation (exact / contains / regex) that turns each row into a match or mismatch badge, plus an auto-refresh selector (off / 20 s / 60 s) that stops when every row matches. Show a progress timeline of matched locations over time (dnschecker).
- Show TTL as a human countdown ('cache expires in 3m 50s') rather than raw seconds, with the raw value in a tooltip (nslookup.io 'Revalidate in', Google Dig '1 minute').
- Resolver tabs on Lookup (Cloudflare / Google / Quad9 / … / Compare all), with a 'Compare' mode highlighting cells that differ between resolvers (nslookup.io tabs, digwebinterface 'Compare output').
- Provenance stamp on every result: 'Resolved via Google DoH · answered by NS 205.251.198.171 · 2026-09-23 09:05 UTC · 312 ms' (MxToolbox 'Reported by … on …', dns.google 'Comment', SSL Labs 'Assessed on').
- Per-row pivot actions (kebab ⋮ or inline links): IP → IP Intel / Blacklist / Reverse IP / Probe cert; host → Lookup / Global / Health; NS/MX targets are clickable links that open their own lookup (MxToolbox 'Blacklist Check · SMTP Test', DNSDumpster ⋮, nslookup.io linked NS/MX).
- 'Copy as command' on every query row: dig / kdig / doggo / curl DoH, plus a Raw toggle showing dig-style zone-file lines (digwebinterface 'Show command', Google Toolbox 'Raw View', dns.google 'resolve directly at &lt;API URL&gt;').
- Web | JSON toggle on detail cards, with a copy-JSON button (ipinfo), and annotated JSON for DNS messages ('Status: 0 /* NOERROR */') (dns.google).
- Dense host rows with secondary info stacked in small muted monospace under the primary value: IP with PTR below, ASN with prefix below, provider with country below. This avoids extra columns and keeps 1440px tables readable (DNSDumpster).
- Aggregate mini-charts above big tables (Hosts, Bulk, IP Intel): hosts by provider/ASN as a horizontal bar, by country, and by classification. Clicking a bar filters the table (DNSDumpster Hosting/Networks bars, ipinfo Summarize IPs).
- Tag chips for IP facts: 'Cloudflare', 'CDN', 'Hosting', 'Private', 'Ports 22 80 443', 'RPKI valid', 'Listed on 1 DNSBL'. Use colored chips with text labels, never color alone (ipinfo chips, Shodan port chips).
- CIDR breadcrumb on IP pages ('/8 &gt; /16 &gt; /24 &gt; prefix 140.82.112.0/20 &gt; IP'), each segment clickable to show sibling inventory servers in that range (ipinfo).
- Right-side scrollspy table of contents on long result pages (Certificate, Health, IP Intel) with section anchors, which work as deep-link permalinks (ipinfo, internet.nl verdict list linking to sections).
- TXT records as vendor chips ('Google Workspace verification', 'Microsoft 365', 'Stripe'…) and SPF as numbered plain-English steps with a lookup counter '9/10 DNS lookups'. No external logos, to stay within the CSP (nslookup.io).
- Structured record renderers: an SOA field table with human durations (Refresh 2h, Expire 14d, Negative TTL 1h), MX with a 'Primary' badge on the lowest preference, CAA grouped by tag, SVCB/HTTPS params as key chips (nslookup.io).
- Certificate card: big days-left badge with color bands (≤0 expired, ≤30 red, ≤60 amber), relative text ('expires in 1 month 9 days'), and dual-cert awareness when RSA and ECDSA certs exist. Show CAA results inline next to the issuer (SSL Labs).
- CT table: collapse precert+leaf duplicates into one row with a 'precert' badge, add a 'Group by issuer' toggle, and put CSV/JSON download icons in the table header (crt.sh, fixing its duplicate-row noise).
- DNSSEC chain as an inline SVG graph with a status legend and counts ('Secure 8 · Insecure 1 · Warnings 1') and a Download SVG button (DNSViz).
- Timestamped permalinks plus a 'Share snapshot' link that encodes compressed results in the hash (CompressionStream, no backend), rendered read-only with an 'as of' stamp (internet.nl permalink, MyIP shareable reports).
- Print stylesheet: hide the nav and controls, expand all disclosures, keep status text labels, add a header with query + timestamp + tool URL, so 'Save as PDF' yields a customer-ready report (SSL Labs/internet.nl-style reports).
- Export menu on every table: CSV (with BOM for Excel), JSON, 'copy as Markdown table', and names.txt/targets.txt for the CLI (crt.sh CSV/JSON icons, DNSDumpster xlsx, web-check 'Export Data').
- Quota and rate-limit meters next to each third-party source: 'HackerTarget 12/50 today', 'Globalping 236/250 this hour' from the X-RateLimit-Remaining header. Show a clear 'rate-limited, retry in 42 min' state instead of a generic error (none of the surveyed tools do this well).
- Avoid what made the incumbents feel dated or hostile: no ads or upsell cards above results (dnschecker GoDaddy banners, nslookup.io 'Track this domain', MxToolbox 'Solve Email Delivery Problems'); no captcha or bot walls (web-check.xyz Vercel checkpoint, SecurityTrails 'Just a moment'); no result caps (DNSDumpster 50 of 335); no blurred paywall sections (ipinfo); no SEO text walls under the tool (dnschecker, whatsmydns); no cookie bar covering results. Keep 'free, no limits, runs in your browser, nothing leaves your machine' visible as a feature line.
- Empty states that teach: before the first query, show 3 clickable example queries (e.g. 'github.com MX', '1.1.1.1', 'AS13335') and a one-line explanation per view (nslookup.io 'try wikipedia.org', Zonemaster), rather than a blank form (DNSDumpster/Zonemaster landing).

### UI patterns

- A Before → During → After stepper across the SSL workflow: Find targets (scan) → Rollout Board (per-server checklist) → Verify (CLI JSON import + Globalping probe) → Report. The current phase shows in the header with a progress bar such as '37/41 verified'.
- Kanban/board cards per server with status columns todo/doing/done/verified plus a 'CDN-managed, no install' column. Status chips always carry text and an icon, never colour alone.
- Evidence badges on every 'verified' claim showing the source and time, e.g. 'CLI 14:02 from jump01', 'Globalping Frankfurt AS3320 14:05 serial …a5', 'CT only (not deployment)'.
- A diff view (added/removed/changed) reused for old-vs-new certificate SANs, snapshot-to-snapshot scans, zone-file-to-live drift and CT new issuances. Colours have +/−/~ glyphs for accessibility.
- A quota meter in the header (Globalping X-RateLimit-Remaining, hackertarget daily, certspotter 429 state), with a confirm dialog before bulk actions that would exceed it.
- A 'Copy as…' menu on every row: dig/doggo/Resolve-DnsName/curl --resolve/openssl s_client/ssl_origin_scan.py.
- A row context menu (and keyboard shortcut) to pivot any value into another tool with it prefilled: IP → IP Intel/RPKI/DNSBL/Globalping SNI probe; host → Lookup/Global/Health; certificate → CT search.
- A command palette (Ctrl+K) that accepts a domain, IP or pasted PEM and suggests the right view, like doggo/quien single-entry UX.
- A live countdown and ETA for propagation ('all caches refreshed by 14:32'), plus a watch mode that updates the tab title and favicon badge and fires a Notification when consistent.
- A world/country grid with flags for ECS vantages and real-ISP Globalping probes, grouped into consistency clusters with the same colour per answer group and the group label in text.
- Severity-grouped checklists (error/warn/info/ok) with a 'why it matters' and a 'how to fix' snippet per check, in the Internet.nl and learndmarc explanatory style.
- An expandable SPF include tree and DNSSEC chain graph (inline SVG) with per-node lookup cost or signature status.
- Print-optimised report layout (@media print, page breaks, no nav) and a 'Download self-contained HTML' button for customer hand-over, bilingual TR/EN.
- Local-first privacy banners on views that handle certificates or inventory ('never leaves this browser'), and a clear-data button next to any stored key or snapshot.
- Shareable state in the URL #fragment (deflate-raw + base64url) with a size guard and a warning when the payload includes IPs or inventory.
- An empty-state 'try an example' for each tool, plus deep links (#/global?name=…&amp;type=…) that tickets and chat messages can embed.

## Measured results (2026-09-23)

Live runs of the wired discovery engine (`runScan`) from Node 22 over HTTP/2 DNS-over-HTTPS, with the same DoH shim and passive-source replay cache as `tests/live/benchmark-discovery.mjs` (the level × locale × learned-names matrix ran from a scratch harness around them and is not committed). Passive sources were limited to Anubis, ip.thc.org and crt.sh, because the anonymous HackerTarget, OTX and Cert Spotter quotas of the test IP were used up; permutations were on (budget 1,500). The two private customer domains, their known names and their known origins come only from the gitignored `tests/live/targets.local.json`; they are reported by number, never by name.

### Recall against known names

| Domain | Level | Locale packs | Found / known | Wall time | DoH requests/s |
|---|---|---|---:|---:|---:|
| private #1 | Smart | auto (no pack) | 17 / 27 | 46 s | 189 |
| private #1 | Smart | a locale pack, chosen manually | 21 / 27 | 28 s | 318 |
| private #1 | Large | auto (no pack) | 21 / 27 | 187 s | 277 |
| private #1 | Large | the same locale pack | 21 / 27 | 239 s | 219 |
| private #1 | Huge | auto / locale pack | still running when the window closed — not measured | — | — |
| private #2 | Smart | auto | 4 / 4 | — | — |

- The manually chosen locale pack reaches the same names as the Large tier, in a fraction of the time (28 s against 187 s); Large adds nothing else on this domain.
- The remaining misses are organisation-specific names. None of them is in any vendored public list (SecLists top-1M, bitquark, commonspeak2) or in a locale pack, no certificate for them was in Anubis, ip.thc.org or crt.sh, and permutation of the found names does not produce them. They were deliberately **not** added to any list (a list must never be tuned to one customer's zone). They can only come from a custom wordlist, learned names carried over from an earlier scan, or a zone export ([ROADMAP P1.2](ROADMAP.md#p12-zone-import-exact-seeds-proxied-origin-map-lint-and-live-drift)); guessing tops out at 21 / 27 here.

### Learned names across domains

Private #2 was scanned first with an empty learned store, and its labels were passed to a scan of private #1 as `learnedLabels`. Recall stayed at 17 / 27. The labels were used — six finds moved from permutation hits to direct wordlist hits (wordlist 10 → 16, permutation 6 → 0), so they no longer depend on the permutation budget — but none of #1's missing names occurs on #2. Learned names raise recall only when the earlier scan saw the distinctive labels.

### Origin candidates

Private #1's proxied names have known real origins. Every known origin IP fell inside its host's computed `candidateNetworks` and inside `result.cliTargets`, so the suggested sweep command would reach all of them.

### False positives

Names found only by DNS guessing (wordlist, permutation, recursive round) were re-checked independently through `https://dns.google/resolve`, together with a random sibling label under the same parent to catch wildcard artefacts:

| Domain | Level | DNS-only finds | Re-checked | False positives |
|---|---|---:|---:|---:|
| private #1 | Smart | 17 | 15 | 0 |
| github.com (8–10 wildcard parents) | Smart | 63 | 15 | 0 |
